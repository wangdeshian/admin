# 行政流程圖共用版（未上線）

Existing board stays unchanged. Provision a **new** Firebase project and web app, enable the Google sign-in provider, add `wangdeshian.github.io` to Authentication authorized domains, and create a Firestore Standard database in production mode. Do not change either existing site's Firebase project. Configure the new project's Firestore Security Rules using firestore.rules before making the web config available. In the private Firestore console, create one `adminWorkflowMembers/{verified Google sign-in email exactly as returned}` document per approved member (a boolean field such as active=true is sufficient; revocation deletes the entire document). Do not put account addresses, credentials, or service-account keys in GitHub. Set firebase-config.mjs to the new project's public Web SDK configuration only after the rules are in place. Release the /workflow/shared/ path without changing /workflow/.

Verify before migration: signed-out access fails; a Google account without a membership document cannot read or write; an authorized owner and authorized test collaborator can read and persist a synthetic record across devices; simultaneous stale saves fail without overriding draft or cloud values. Use the browser's old board JSON export only with the owner's go-ahead: it can include internal data, and importing replaces the shared copy. Use a synthetic record first. Remove synthetic test data and access afterward. See [Firebase sign-in](https://firebase.google.com/docs/auth/web/google-signin) and [Firestore rules](https://firebase.google.com/docs/firestore/security/get-started).
